# Grill decisions: UI from design_handoff_fuel_price_dashboard

- D1 (Q1): Split the UI into three specs, done in order: 002 public views (Dashboard plus shared layout, theme and responsive shell), 003 sign-in and Contribute, 004 admin. Analytics goes with whichever spec adds price history. Rejected: one spec for all screens (O2), user/admin split (O3).
- D2 (Q2): Analytics is out of 002 and gets its own later spec (005) once real price history exists. 002 needs no backend changes, and the nav shows only working tabs. Rejected: Analytics in 002 with a new price-at-date backend function (O5).
- D3 (Q3): The ranking and "Cheapest in CDO" show each station once per fuel category, using its cheapest product in that category, with the product name beside the price. Rejected: every product as its own row (O7), all products listed inside one station row (O8).
- D4 (Q4): The price adjustment card uses each fuel's latest week of shifts across brands: one amount when all brands agree, a range when they differ in the same direction, "Mixed" when directions differ, and "No adjustment recorded yet" when there are none. Rejected: every brand listed (O10), average across brands (O11).
- D5 (Q5): Each ranking row shows the report date in days ("Reported today", "Yesterday", "12 days ago") and adds "· est." as text when a shift applied, with a one-line legend under the ranking. Rejected: only the newer date (O13), both full dates (O14).
- D6 (Q6): No palette picker. Teal (hue 190) is the only palette, and the other four were design-tool options. Rejected: user palette picker with five palettes (O16).
- D7 (Q7): First visit follows the OS preference (prefers-color-scheme). The toggle choice is saved in localStorage and applied by an inline script in app.html before paint. Rejected: dark on first visit with saved toggle (O17), dark every visit with session-only toggle as in the mock (O19).
- D8 (Q8): The full header ships in 002 with Dashboard, Analytics and Contribute tabs, and the hamburger menu on mobile. Analytics and Contribute link to their own pages that show "Coming soon" until their specs build them. Rejected: logo and theme toggle only, no tabs (O20).
- D9 (Q9): No login buttons or user menu in 002. They come with real sign-in in 003. Rejected: login buttons leading to a "Coming soon" page (O23).
- D10 (Q10): The app is named "CDO Fuel Price Tracker" in the logo and tab title. On mobile the logo text is adjusted to fit (sizing or wrapping decided in the build). Rejected: "PumpWatch" as designed (O24).
- D11 (Q11): The station ranking shows 10 stations per page with the mock's Prev / Page N of M / Next controls. Stations with no approved price are not ranked. Rejected: 5 per page as in the mock (O27), no pagination (O28).
- D12 (Q12): The Dashboard loads prices and shifts on the server (+page.server.ts) with public read access. With no prices, the ranking and "Cheapest in CDO" show "No prices reported yet". If loading fails, a SvelteKit error page says "Prices couldn't load. Try again later." and never shows old or zero prices. Rejected: browser-side loading with skeletons (O30).
- D13 (Q13): Fonts are self-hosted. The .woff2 files for only the weights used (Inter 400/500/600, Montserrat 500/600/700, Roboto 400/500/700) go in static/fonts/ and are declared with @font-face in app.css. No new dependencies and no third-party requests. Rejected: Google Fonts link (O32), @fontsource packages (O33).
- D14 (Q14): Done means: Vitest tests written first for the three pure functions (cheapest product per fuel, shift summary, age and est. label); one Playwright smoke test on invented data (ranking loads, fuel switch re-ranks, pagination, theme persists after reload, mobile hamburger, Coming soon pages, empty state); visual match checked by eye against the mocks in dark and light, desktop and mobile; npm run check, lint and tests pass. Rejected: adding Playwright screenshot comparisons (O35).
- D15 (Q15): The server reads Supabase with @supabase/supabase-js (approved and installed as a runtime dependency, ^2.119.0). @supabase/ssr waits for sign-in in 003. Rejected: plain fetch to PostgREST with no dependency (O36).
- D16 (Q16): Ranking rows show "street address, barangay" under the brand. "Cheapest in CDO" shows "Brand · Barangay". Rejected: barangay only everywhere (O39).
- D17 (Q17): "Cheapest in CDO" rows show the report age and "est." in the ranking's format, for example "Petron · Lapasan · 2 days ago · est.", so Constitution Principle I holds. FR-008 and US1 scenario 7 updated. Rejected: keep the mock and record a justified exception (O41).
- D18 (Q18): Colour tokens in app.css are rewritten with light-dark(), with color-scheme "light dark" on :root and [data-theme] overriding it, so the first visit follows the device even without JavaScript. The two shadow tokens get their own light and dark rules. The inline script only applies a saved choice. Rejected: script only, with no-JS visitors always dark (O43), and duplicating the light tokens in a media query (O44).
- D19 (Q19): No Content Security Policy in 002. OPEN-QUESTIONS.md records that CSP must be configured before the first deploy, in a small hardening spec after 003. Rejected: configure kit.csp in 002 with a nonce on the theme script (O46).
